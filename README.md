# ChatGPT Local Bridge

A Windows-local filesystem bridge for ChatGPT-style MCP clients. It gives the model direct, bounded access to explicitly allowlisted project folders while keeping the source tree on the PC.

The default one-click setup is tuned for:

\`\`\`text
project = mu-rnd-5.2
root = %USERPROFILE%\Desktop\MU-RND-5.2
\`\`\`

## Architecture

\`\`\`text
ChatGPT
   |
   | OpenAI Secure MCP Tunnel
   v
tunnel-client on Windows
   |
   | localhost only
   v
127.0.0.1:8765/mcp
ChatGPT Local Bridge
   |
   v
Explicit allowlisted project roots
\`\`\`

No VPS, public port, domain, reverse proxy, Docker, or always-on home server is required.

## One-click Windows setup

Double-click:

\`\`\`text
INSTALL AND START.cmd
\`\`\`

It automatically:

1. finds Python;
2. creates/reuses \`.venv\`;
3. installs dependencies;
4. configures \`%USERPROFILE%\Desktop\MU-RND-5.2\` as the allowed root;
5. generates/reuses a strong local token;
6. enables normal file editing;
7. keeps delete and general command execution disabled;
8. installs the tunnel client when possible;
9. registers the bridge in the current user's Windows Startup folder;
10. starts the bridge in the background;
11. starts the tunnel automatically when tunnel credentials are already configured.

The bridge starts automatically on future Windows logins.

Convenience launchers:

\`\`\`text
START.cmd
STOP.cmd
STATUS.cmd
CONNECT CHATGPT.cmd
\`\`\`

\`CONNECT CHATGPT.cmd\` is only needed once if Secure MCP Tunnel credentials have never been configured on the machine. A Tunnel ID and runtime API key are authorization credentials and cannot be generated by this repository.

## Filesystem MCP tools

Read/navigation:

- \`projects\`
- \`health\`
- \`list_directory\`
- \`directory_tree\`
- \`stat\`
- \`search_files\`
- \`search_text\`
- \`read_file\`
- \`read_multiple_files\`
- \`read_range\`
- \`hash_file\`
- \`git_status\`
- \`git_diff\`

Editing:

- \`write_file\`
- \`apply_patch\`
- \`create_directory\`
- \`move_file\`
- \`rename_file\`

Guarded tools:

- \`delete_path\` — requires \`BRIDGE_ALLOW_DELETE=true\`; default is off.
- \`run_command\` — requires \`BRIDGE_ALLOW_COMMAND=true\` and an explicit executable allowlist; default is off.

Earlier binary-research tools are retained: \`pe_info\`, \`pe_sections\`, \`va_to_offset\`, \`read_va\`, \`find_bytes\`, \`strings\`, and \`disassemble\`.

Backward-compatible \`list_files\` and \`read_text\` aliases are also retained.

## Safety model

All tool paths are relative to an allowlisted project root. Absolute paths are rejected. Paths are canonicalized before use and resolved targets outside the configured root are rejected, including existing symlink/junction escapes.

Writes are atomic. \`write_file\` and \`apply_patch\` support \`expected_sha256\` optimistic concurrency checks so an edit can fail instead of silently overwriting a file that changed since it was read.

Git access is intentionally read-only (\`status\` and \`diff\`). General shell execution is not used by filesystem tools.

Audit records are written to \`bridge-audit.log\` by default.

See \`docs/SECURITY.md\` and \`docs/ARCHITECTURE.md\`.

## Configuration

\`INSTALL AND START.cmd\` writes \`.env\` automatically. The important defaults are:

\`\`\`env
BRIDGE_PROJECT_ID=mu-rnd-5.2
BRIDGE_ROOT=C:\Users\<you>\Desktop\MU-RND-5.2
BRIDGE_ALLOW_WRITE=true
BRIDGE_ALLOW_DELETE=false
BRIDGE_ALLOW_COMMAND=false
\`\`\`

For multiple projects, set \`BRIDGE_PROJECTS_JSON\` instead of the single project pair.
